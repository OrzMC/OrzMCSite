**Eaglercraft** 是把 Java 版客户端编译到浏览器的项目，跑的还是原版协议，所以浏览器玩家能进真实的 Java 服务器——前提是服主做了桥接与 TLS 适配。本页只讲两件事：玩家怎么用、服主怎么接。

## 玩家：三步进服

1. **打开客户端**：[Eaglercraft 26.3](https://eaglercraft.com/play?version=26.3)（无需安装，首次要下载几十 MB）。
2. **连服**：多人游戏 → 直连（Direct Connection），粘贴服务器卡片上的 **Web客户端连接地址**（`wss://` 开头；点卡片上的「在浏览器中玩」会自动复制）。
3. **登录**：首次 `/register 密码 重复密码`，之后 `/login 密码`。账号与 Java 版共用——**同名即同一玩家**（背包、位置、权限一致）。

尚未加白名单会被拒绝，先看[玩家手册](/user/)。

### 卡顿 / 掉线先查这三项

- 浏览器**硬件加速**已开（`chrome://gpu` 看 Hardware accelerated），只留一个游戏标签
- 游戏标签**保持前台**，别锁屏或休眠；优先有线 / 5 GHz
- 仍卡再降低游戏内视野

> 实测：同一台机器、同一个服，硬件加速能连十几分钟不掉，纯软件渲染几分钟就断——先查客户端环境，再怀疑服务器。

## 服主：适配最佳实践

1. **选形态**：单服直挂 EaglerXPaper（最省事，但改不了玩家 UUID、不支持 Folia）；多服 / 大厅 / Folia 用 Velocity + EaglerXServer（可统一身份）。
2. **整链离线模式**：代理与后端都要 `online-mode=false`（桥接层不支持在线登录）。浏览器玩家是离线 UUID，**同名 = 同账号**，所以白名单 + 登录口令是唯一的门。
3. **给一个 `wss://` 入口**：浏览器只认 TLS。用已有反向代理终结证书（建议单独子域），透传 WebSocket 的 `Upgrade`、关闭缓冲，并把真实 IP 头传给桥接层，否则会被拒连。
4. **身份加固**：白名单收紧、登录插件强制口令、op / 权限名字提前注册（权限按命名规则派生的 UUID 授权）；与基岩端共存时只给基岩组放行反作弊。
5. **上线验收**：客户端版本与后端协议对齐（26.3 客户端连 26.3 后端）、浏览器真机进服、三端同服、断线重连、回滚演练。

拓扑、端口与排障细节见 [`deploy` 文档](https://github.com/OrzMC/OrzMCDeploy/blob/main/docs/eaglercraft-deploy.md)。

## 版本与其它选择

- **按服务端选版本**：后端是 26.3 就用 26.3 客户端（最新）；老服（1.8 / 1.12）用对应版本。
- [MCJS 中文站](https://www.mc.js.cool/)：中文汉化 + 多版本一站式，自带联机中继。
- [Minecraft Classic](https://classic.minecraft.net/)：官方 2009 经典版，只有创造、不能联机，仅适合试玩。
