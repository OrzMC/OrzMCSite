想在浏览器里直接进服，先要搞清楚**跑的是什么**：官方从未提供 Java 版网页客户端，能在网页里跑接近原版 Minecraft 的，都是社区用 TeaVM / WebAssembly 把 Java 客户端重新编译出来的移植版。它们说的仍然是 Java 版协议，所以**能连真实的 Java 服务端**——前提是服务端做了对应适配。

本页分两部分：前半是 2026 年 11 月的方案盘点（版本、体量、能力边界），后半是**服务端接入 Eaglercraft 客户端的最佳实践**，内容来自我们在测试服跑通「Java + 基岩 + Web 三端同服」的实测。

## 一、浏览器里能跑什么

| 层级 | 代表 | 本质 | 能否连你的 Java 服 |
|:--|:--|:--|:--|
| 官方复刻 | [Minecraft Classic](https://classic.minecraft.net/) | 2009 版 Classic 的官方网页版 | 否（无联机） |
| 协议移植 | [Eaglercraft](https://eaglercraft.com/) | Java 客户端编译到 JS/WASM，跑原版协议 | 能（服务端需桥接） |
| 中文整合 | [MCJS](https://www.mc.js.cool/) | 汉化 + 多版本收纳的 Eaglercraft 镜像站 | 能（同上） |

一句话选型：**只想试玩 → Classic；要和 Java 服玩家一起玩 → Eaglercraft 系**。

## 二、2026 年 11 月现状盘点

### 2.1 官方：Minecraft Classic

- 打开 [classic.minecraft.net](https://classic.minecraft.net/) 即可玩，**必须用键盘**（移动端会直接提示不支持），且要求浏览器支持 WebGL / WebRTC。
- 能力停在 2009 年的 Classic：创造模式、方块放置与破坏，**没有多人联机**，与 Java 版服务器完全无关。
- 适合：给没装客户端的朋友看一眼「方块游戏长什么样」，不能作为社区入口。

### 2.2 Eaglercraft：事实上的标准

官网 [eaglercraft.com](https://eaglercraft.com/) 在 2025 年 8 月做过一次整站重写（官方新闻 *Eagler Site Recode*），现在是完整的平台而不只是一个启动页：

- **多版本**：26.3 / 26.2 / 1.8.8 / 1.12.2，以及 1.5.2、Beta 1.7.3 等怀旧版与模组整合包。
- **账号与云存档**：登录后可把单人世界同步到云端（跨设备继续玩）。
- **服务器目录**：按票数排名，直接显示在线人数与版本标签（1.8 / 1.12 / 26.x）。
- **共享世界**：单机世界开「Invite」得到加入码，别人凭码进你的世界（中继模式，不需要自建服务端）。
- **资源包**、**新闻**、**离线下载**（zip 内含单文件 HTML）、多语言（含简体中文）。

**26.3 是最新版本，也是「真的是 Minecraft」的那一版**（官网首页的快捷入口目前仍默认列 26.2 / 1.8.8 / 1.12.2，26.3 在版本库里选）：

| 项 | 值 |
|:--|:--|
| 对应 Java 版 | **26.3**（协议号 **777**） |
| 客户端形态 | 单个 HTML 文件，约 **75 MiB**（78,124,802 字节） |
| 官方分发 | zip 约 **56 MiB**（58,885,242 字节），解压后是那个 HTML |
| 握手协议 | Eaglercraft **v5**（客户端同时声明 3/4/5，服务端按最高可用协商） |
| 运行要求 | 支持 **WebAssembly GC + WebGL2** 的现代浏览器 |

两个容易踩的事实：

1. **握手里的品牌字符串是滞后的**（通过 26.3 客户端握手仍自报 `Eaglercraft 26.2`），判断版本请用协议号，不要用品牌串。
2. **有好多条并行构建线**：官方站托管的 26.3（brand 为 `o_xer + Eaglercraft.com`，2026-11 仍在更新）、社区移植的 26.2（u2）、MCJS 收录的 hatrix 26.3（u1，已停更）。**选哪个版本取决于你的桥接层支持哪个协议**，不要只看版本号大小。

### 2.3 中文整合站：MCJS

[MCJS](https://www.mc.js.cool/) 是 2022 年起的汉化 + 收纳项目（2026 年满四周年），对我们这类中文社区的价值是**开箱即中文、多版本一站式**：

- 版本覆盖从 1.5.2 / 1.6.4 / 1.9.4 / 1.12.2 一直到 1.21.11、26.2、26.3，另有 1.6.4 Forge 的轻量/科技/天空工厂/魔法整合包。
- 每个版本都提供 **WASM-GC 与 JavaScript 两种构建**（例如 1.8.8：WASM-GC 约 9.7 MB、JS 约 21.2 MB；26.3：约 75 MB）。
- 支持触屏操作与**远程联机**（自带中继），不需要自己有公网服务端。
- 需要留意：它自己也标注了哪些版本已停更（如 26.3 u1、1.20.6、1.16.5、1.14.4、1.13.2），选版本前先看这一列。
- 定位是**社区汉化分支，非官方**，问题反馈要找对应上游作者。

### 2.4 横向对比

| 方案 | 版本上限 | 联机 | 中文 | 合规风险 |
|:--|:--|:--|:--|:--|
| Minecraft Classic | 2009 Classic | ❌ | ✅（官方多语言） | 无（官方） |
| Eaglercraft（官网/离线版） | 26.3（协议 777） | ✅ 服务器目录 / 共享世界 | ✅ | 高（见第 7 节） |
| MCJS | 26.3 / 1.21.11 等 | ✅ 自带中继 | ✅ 汉化最佳 | 同上（同源分支） |

## 三、Eaglercraft 是怎么连上真实 Java 服的

链路很短，但每一环都有约束：

```text
浏览器（Web 客户端）
   │  wss://（TLS only，26.3 拒绝明文 ws）
   ▼
EaglerXServer / EaglerXPaper（桥接层）
   │  原生 Java 协议（26.3 = 777）
   ▼
Paper / Folia 后端
```

关键事实（都经过实测验证）：

1. **26.3 只接受 TLS**：客户端默认尝试 `wss://`，连明文端口直接失败。
2. **桥接层一律是「离线」的**：它向后端发的是离线 `Login Start`，玩家 UUID 由名字派生（`OfflinePlayer:<名字>` 的规则），与离线 Java 服一致。后端开 `online-mode=true` 会被直接踢掉（`Your client does not support online mode`）。
3. **只有代理能改 UUID**：Velocity / BungeeCord 可以改写 Eagler 玩家的 UUID；Bukkit 平台（EaglerXPaper）不能。
4. **端口不是「另开一个游戏端口」**：代理模式下，桥接插件注入的是**已有监听器**，浏览器和 Java 玩家连的可能是同一个 443/端口，只是协议不同（详见 5.1）。

## 四、我们的实测结论（OrzMC 测试服）

我们用的是「**Velocity 4.3.1 + EaglerXServer 1.1.1 + Paper 26.3**」这条链路，另外验证过 Folia 后端：

| 项 | 结果 |
|:--|:--|
| 浏览器进服 | ✅ 可玩（任务、背包、被怪物击杀都正常） |
| 三端共存 | ✅ Java + 基岩（Geyser）+ Web 同服、互相可见、聊天互通 |
| Folia 后端 | ✅ 可玩（但必须走代理；直挂模式不支持 Folia） |
| 插件矩阵 | ✅ LuckPerms / EzShops+Vault / ViaVersion / GrimAC / LoginSecurity / SkinsRestorer / EssentialsC 均正常；Simple Voice Chat 对 Web 端不适用 |
| 身份一致性 | ✅ 同名 = 同 UUID = 同一份存档与权限（Java / 基岩 / Web 共享名字空间） |
| 握手 | ✅ 协商 `eagler=5` / `mc=777`，登录放行 `ALLOW_LOGIN` 且 UUID 稳定 |

**一个反直觉的坑：浏览器「玩几分钟必掉线」（错误码 1006）通常不是网络问题。**

实测同一服务端、同一客户端，只换渲染后端：

| 渲染方式 | 结果 |
|:--|:--|
| 纯 CPU 软渲染（SwiftShader） | 3–6 分钟必掉（服务端日志是 keepalive 超时踢人） |
| 硬件渲染（D3D11） | 连续 10 分钟以上不掉 |

也就是说：**浏览器端渲染卡顿 → 漏回心跳 → 服务端判超时 → 反代关连接 → 客户端显示 1006**。所以先让玩家确认「硬件加速已开、游戏标签在前台、别锁屏」，再考虑降服务端视野。

## 五、Java 服务器接入 Eaglercraft 的最佳实践

以下按「先定拓扑 → 再对齐版本 → 再接 TLS → 最后收紧身份与网络」的顺序，顺序反了会白折腾。

### 5.1 选拓扑：直挂还是走代理

| 形态 | 组件 | Java 玩家入口 | Folia | 改写 UUID | 适用 |
|:--|:--|:--|:--|:--|:--|
| **直挂**（direct） | EaglerXPaper 插件 | 与 Web 共用实例端口 | ❌ | ❌ | 单服、原版 Paper、快速验证 |
| **代理**（proxy） | Velocity + EaglerXServer | 由代理发布 | ✅ | ✅ | 多服/大厅、Folia、要统一身份 |

- **直挂最省事**：装 [EaglerXPaper](https://github.com/PlanetDogeCodes/EaglerXPaper)（第三方把上游 Bukkit 分支前移到 1.17–26.x 的反编译再改产物），实例端口同时兼任 WSS。注意它**不支持 Folia**，且许可证为 *All Rights Reserved*——只当二进制用，不要二次分发/改源码。
- **代理是长期方案**：[Velocity](https://papermc.io/software/velocity) + [EaglerXServer](https://github.com/lax1dude/eaglerxserver) 注入现有监听器，能改 UUID、能挂多后端、Folia 也能用。
- 两种形态都是**一个开关**，切换时记得停用另一套插件（否则 Web 端点仍可连）。

### 5.2 版本对齐

- 26.3 客户端**只声明 MC 777**，后端不在 777 且没装 Via 就进不来；老客户端（v3/v4）另有 `max_minecraft_protocol` 上限（默认 340 = 1.12.2）。
- v5（26.x）默认不限 MC 协议（`max_minecraft_protocol_v5 = -1`），**真正的约束是后端版本**。
- 建议：先让桥上与后端版本号一致，再考虑 ViaVersion 做跨度兼容；Via 只解决协议转换，不解决桥接层自己的问题。

### 5.3 TLS / WSS 反向代理

浏览器只认 `wss://`，TLS 必须在某一层终结。最佳实践是用你已有的反代（Caddy / Nginx）终结，而不是给游戏端口单独签证书：

```nginx
# Caddy 片段要点（示意）
play.example.com {
    reverse_proxy 127.0.0.1:8081 {
        header_up X-Real-IP {remote_host}   # 桥接层要它，缺了直接断
        flush_interval -1                  # WebSocket 长连接必须禁用缓冲
    }
}
```

四条硬要求：

1. **透传 `Upgrade` / `Connection`**：否则握手阶段就失败。
2. **必须给 `X-Real-IP`**：把桥接配置里的 `forward_ip = true` + `forward_ip_header = X-Real-IP` 打开，**只允许反代入口**——直连桥接端口的连接会被拒绝，这是刻意的安全设计。
3. **别开压缩缓冲**：`flush_interval -1`（Caddy）/ `proxy_buffering off`（Nginx）。
4. **域名与证书**：给 Web 端单独一个子域（如 `play.`）最省心；与面板/EasyBot 复用 443 时按 Host 分流即可，不必新开端口。若 443 不可用，退到备用高位端口（我们用 18443），并在站点上如实展示 `wss://<域名>:<端口>/`。

### 5.4 身份与安全（最容易翻车的一节）

桥接层的默认行为是「不做任何认证」，所以**安全必须由服务端自己补齐**：

1. **整链 `online-mode=false`**：代理和后端都要关。这不是选择，是桥接层的硬限制。
2. **白名单是真正的门**：`white-list=true` + `enforce-whitelist=true`。浏览器玩家和 Java 玩家共享名字空间，**同名即同账号**，所以名单必须收敛（先加白、再让玩家注册）。
3. **口令是第二道门**：装 LoginSecurity（或同类），玩家首次 `/register`、之后 `/login`。要点：
   - 注册窗口 = 已加白但未注册的这段时间，别人可以抢先注册同名的「你的号」；被抢注时用 `/lac rmpass <名字>` 清密码后本人立即注册。
   - 关闭注册（`registration.enabled=false`）会挡住所有新玩家——因为白名单里没有自助建号的入口。
   - **上线前核对所有 op / 权限名字都已注册**：权限按 UUID 授权，而 UUID 由名字派生，未注册的名字等于「谁先注册谁拿权」。
4. **同名双开会被代理拒**：同一名字同时在线时，后到者被挡（`You are already connected to this proxy!`），原会话保留——这是好事，别去「修」它。
5. **别靠名字判断客户端类型**：基岩玩家名是 Xbox 代号，与 Java 名在同一空间；要区分端请用桥接层提供的玩家属性/权限组。

### 5.5 与基岩版共存

三端同服时，Geyser 与 Eagler 是两套独立通道，互不抢占，但有几个细节：

- **Geyser 端口**：`/udp+ /tcp` 同号最省事（`nethernet` + 媒体复用主端口），新版基岩客户端都支持；保留 RakNet 兜底就得多开 UDP 端口。
- **广播地址必须写死域名**：宿主跑着代理/VPN（如 Mihomo TUN）时，STUN 会学到代理出口 IP，外网基岩玩家拿到错误地址 —— 显式配 `advertise-addresses: [<内网 IP>, <域名>]` 并关掉 `stun-discovery`。
- **反作弊要分端豁免**：基岩经 Geyser 转包会被移动类检查误判（表现为「能登录但完全走不动」），给 `bedrock` 组整组 `grim.exempt` 最省事；**浏览器端不需要豁免**（我们实测 5 分钟零 violation），别一刀切关掉反作弊。

### 5.6 稳定性与性能

- **客户端侧**：确认硬件加速、游戏标签保持前台（后台标签会被浏览器节流）、别让机器休眠、有线或 5 GHz 优先。1006 掉线优先查这里。
- **服务端侧**：给 Web 端降负载的手段在 26.x 上有限（按玩家改视野的插件可能与桥接层冲突），最稳的是**全局降 `view-distance`**（6 → 5 或 4）。
- **心跳容错**：适当放宽超时（例如 `velocity.toml` 的 `read-timeout` 调到 120000、`spigot.yml` 的 `settings.timeout-time` 调到 180），给弱网/低端设备留余量。
- **帧长上限**：把 `http_websocket_max_frame_length` 从默认 131071 降到 65535，安全与内存都更稳。

### 5.7 上线验收清单

按顺序勾，任何一项不过就别开白名单：

- [ ] 桥接启动日志出现监听器注入成功（Velocity 方法）且无插件报错
- [ ] 握手协商结果：`eagler=5` / `mc=777`（与后端版本一致）
- [ ] 登录放行：两次连接得到**同一个** UUID
- [ ] 浏览器真机能进服，HUD/移动/背包正常
- [ ] 三端共存：Java + 基岩 + Web 同时在线、互相可见
- [ ] 断线重连 30 秒后能回来，背包与位置合理
- [ ] 反代日志能看到 `/ws` 类请求，玩家 IP 不是反代地址（`X-Real-IP` 生效）
- [ ] 直连桥接端口会被拒（`forward_ip` 生效）
- [ ] 回滚演练过：关掉开关后 Java 玩家入口恢复正常

### 5.8 故障速查

| 现象 | 多半是 |
|:--|:--|
| 浏览器 `Could not connect to direct EaglerX WebSocket` / `1006` | 用 `wss://` 连了明文端口，或反代没透传 `Upgrade` |
| `Connected without a "X-Real-IP" header, disconnecting` | 绕过了反代直连桥接端口 |
| `Your client does not support online mode` | 代理或后端仍是 `online-mode=true` |
| 握手成功但 `Invalid Username` | v5 的用户名取自握手包的 `auth_username`，不是登录包 |
| 玩几分钟必掉、服务端日志是 keepalive 超时 | 客户端渲染卡顿（先查硬件加速/后台标签），再考虑降视野 |
| 玩家 IP 全是反代地址 | `forward_ip` / `forward_ip_header` 与反代实际请求头不一致 |
| 基岩能登录但走不动 | Geyser 转包被判移动异常 → 给基岩组反作弊豁免 |

## 六、玩家侧：怎么连我们的服务器

1. 打开 [eaglercraft.com](https://eaglercraft.com/)（或 [MCJS](https://www.mc.js.cool/) 选 26.3 / 1.8.8 等版本），进游戏。
2. 服务器卡片上的 **「Web客户端连接地址」** 就是给你填的地址，形如 `wss://<域名>:<端口>/`，点一下即可复制。
3. 客户端里：**多人游戏 → 直连（Direct Connection）→ 粘贴地址 → 加入**。
4. 首次进服同样要 `/register` 注册口令（与 Java 玩家共用一套账号规则）；尚未加白名单的玩家会被拒绝，先去玩家群申请，见[玩家手册](/user/)。

提示：Web 端对设备敏感，卡顿时先确认浏览器硬件加速已开、只开一个游戏标签、优先有线网络。

## 七、合规与边界（必须说明）

- Eaglercraft 的做法是**把 Java 客户端反编译后重新编译到浏览器**，这**不符合 Mojang EULA**；EaglerXPaper 还是反编译再改的第三方产物（*All Rights Reserved*）。
- 我们的口径：**只为自建社区开放「接入方式」**，不在本站分发客户端本体、不打包进产品；页面只提供官方入口链接与连接地址。
- 上生产前请自行评估风险与责任边界；对外推广第三方客户端属于你的判断，不属于技术问题。
